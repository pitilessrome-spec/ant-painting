# RAID V0.1 candidate
Default off: ANT_RAID_ENABLED=1 only in a dedicated acceptance environment after migration and authenticated tests. Never enable on production before QA. The 8×8 color-dispatch board is a separate server-authoritative prototype, not the full 3D main puzzle. No ad buffs, no real colony bonuses yet. Team caps 2/3/8, all solo allowed, 4 bosses; room mutations serialized in PostgreSQL, per-member sequences reject duplicate damage and invalid inputs. First unique roster rankings (overall by boss+tier), top-ten world announcements returned for 24h and repeated three times per device, one reward ledger row per player/boss/tier/season. Rewards are records, not yet inventory items. Reconnect uses room ID or invite code. Snapshot polling, not WebSocket. Need live two-user and concurrent PostgreSQL testing, app UI QA, full independent main-board adaptation, anti-bot/rate load testing, season administration, separate ranked assistance verification, inventory and cross-platform identity. No fake data, no unauthenticated sessions.

V0.2: higher minimum HP, server-clock escalating retaliation, separate first-completion and best-duration tables, every verified under-recommended clear qualifies for announcements. Elite power multiplier currently internal test fixture only; no player can equip elevated power yet. Production release stays disabled.

V0.3 adds phase-reset elemental wards: a weak-color attack with >=2 tiles opens a 5.5s combo, a different teammate uses the next color to break one layer; solo can self-chain. While warded ordinary damage is 38%, successful combo finisher 85%. Rank/reward qualification requires all members to participate (at least 3 actions and meaningful damage or two combos). First eligible clear per boss+tier+player grants one server-stored boss relic plus 1/3/6 evolution cores. No client claims, no duplicate grants; evolution usage remains pending. No production activation.

Server-side room recovery lists only the authenticated member's recent open rooms. UI sends retaliation epoch; stale actions refresh without spending turns. Browser QA uses isolated signed test identities (never production Telegram tokens), the actual API handler, real test PostgreSQL and independent mobile browser contexts. This does not replace physical-phone Telegram acceptance.

Q-Ant Evolution candidate V1: starter worker plus eight unlockable species; five levels, immutable earned-core spend ledger with idempotency, relic-gated unlocks, server-derived attack/armor break/resistance/carry attributes, lobby-only loadout frozen at battle start. No client-originated power values accepted. Dedicated elemental support powers, colony-side UI, rare eggs, season tuning, ads and cross-platform sync remain pending. Production not activated.

RAID V0.5 relay candidate: standalone persistent Node WebSocket process, authenticated room subscription and PostgreSQL commit notifications; only invalidation events are sent, authoritative HTTP snapshots/actions remain. Client falls back to HTTP polling, still periodically checks time-based rage. Production requires a separate always-on HTTPS/WSS host, configured RAID_WS_URL and real device acceptance; not deployed on Vercel serverless.
